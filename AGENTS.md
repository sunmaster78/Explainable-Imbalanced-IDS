## 2. Core Research Principles & Architecture

- **Stage 1:** Binary classifier (Normal vs Attack).
- **Stage 2:** Attack-type classifier (DoS, Probe, R2L, U2R, etc.) trained **ONLY on attack rows**, with minority attack classes oversampled using a **conditional WGAN-GP** (PyTorch).
- **Classifiers:** Soft-voting or stacking ensemble of Random Forest + XGBoost + LightGBM.
- **Explainability:** SHAP TreeExplainer.
- **Novelty Claims to Prove:**
  1. *SHAP Fidelity:* Synthetic minority samples generated by WGAN-GP exhibit feature importance profiles consistent with real attacks, outperforming SMOTE.
  2. *Stage-wise SHAP:* Deconvoluting explanations into Stage 1 and Stage 2 provides domain-consistent insights without mixing attack attributes with normalcy.
  3. *Stage-Aware GAN:* A GAN trained exclusively on attack samples achieves higher fidelity than a flat GAN trained across all classes.

## 3. Strict Development Rules

1. **Strict No Data Leakage:**
   - Split data (train / validation / test) **before** any transformations.
   - Fit scalers, encoders, and resamplers **strictly on the training partition**. Never touch test data during feature engineering or threshold tuning.
2. **Validation-Only Tuning:**
   - All threshold calibration and hyperparameter tuning must be executed strictly on the validation set.
3. **Unified Random Seed:**
   - All random number generators (`random`, `numpy`, `torch`, CUDA deterministic flags) must be initialized using `set_seed(seed)` in `src/utils.py`.
4. **Config-Driven Architecture:**
   - Do not hardcode file paths or hyperparameters. Read settings from YAML configuration files in `configs/` (e.g. `configs/nslkdd.yaml`).
5. **Logging over Printing:**
   - Use standard Python `logging` configured via `get_logger()`. Output to both console and `results/logs/`.
6. **Empirical Artifacts:**
   - Every metric table must be saved as CSV in `results/tables/`.
   - Every plot must be saved as 300 DPI PNG in `results/figures/`.
   - Never invent or fabricate numbers.
7. **Read-Only Old Notebooks:**
   - NEVER edit or modify files in `old notebooks/`. You may only view/read them for reference and empirical details. All new modular code must be written in `src/`.
