## 1. Executive Summary & Core Research Architecture

This project implements and evaluates an explainable, two-stage Network Intrusion Detection System (NIDS) designed to tackle severe class imbalance in network traffic.

```
Incoming Network Traffic (Features)
               │
               ▼
┌───────────────────────────────┐
│     STAGE 1 CLASSIFIER        │
│    (Binary: Normal vs Attack) │  --> Classified as Normal? ---> Passed / Safe
└──────────────┬────────────────┘
               │ (Classified as Attack)
               ▼
┌───────────────────────────────┐
│     STAGE 2 CLASSIFIER        │
│ (Multiclass Attack Classifier)│  <--- Trained ONLY on attack samples
│                               │  <--- Minority attacks oversampled with
│                               │       Conditional WGAN-GP (PyTorch)
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│     ENSEMBLE PREDICTION       │  --> Random Forest + XGBoost + LightGBM
│   (Soft-Voting / Stacking)    │      (with validation threshold tuning)
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│   EXPLAINABILITY (SHAP)       │  --> TreeExplainer fidelity & stage-wise insights
└───────────────────────────────┘
```

### Three Novelty Claims to Prove for Research Paper:
1. **SHAP Fidelity of Synthetic Data:** Synthetic minority attack samples generated by the conditional WGAN-GP exhibit feature importance profiles and explanations highly aligned with real attack samples, outperforming SMOTE in explanation fidelity.
2. **Stage-wise SHAP:** Deconstructing explanations into Stage 1 (attack vs normal decision boundary) and Stage 2 (differentiating specific attack families) yields clearer, domain-consistent attribution without conflating attack-specific characteristics with normalcy.
3. **Stage-Aware GAN:** A conditional WGAN-GP trained *strictly on attack samples* achieves higher synthesis quality and downstream minority classification performance than a flat GAN trained across all classes (including normal traffic).

## 2. Strict ML Methodology & Code Quality Rules

Every agent working on this codebase **MUST** adhere to the following rules:

1. **Strict No Data Leakage:**
   - Always perform train/test (and validation) splits **first**.
   - Fit scalers, encoders, and feature selection pipelines **strictly on the training set**.
   - Oversample **strictly the training data**. The test set must never be resampled, scaled with test statistics, or used for tuning.
2. **Validation-Only Tuning:**
   - Hyperparameters, classification thresholds, and ensemble weights must be tuned on the validation set only.
3. **Reproducibility & Single Seed Hub:**
   - Python `random`, `numpy`, and `torch` (including CUDA deterministic flags) must be seeded via a unified `set_seed(seed)` function in `src/utils.py`.
4. **Config-Driven Architecture:**
   - No hardcoded paths or parameters in scripts. All configurations are read from YAML files (e.g., `configs/nslkdd.yaml`, `configs/unsw.yaml`, `configs/cicids.yaml`).
5. **Logging over Printing:**
   - Use standard Python `logging` writing simultaneously to console and `results/logs/`.
6. **No Notebooks for Core Pipeline:**
   - All production logic belongs in modular, typed, well-documented Python modules inside `src/`.
7. **Empirical Integrity:**
   - Never invent or fabricate metrics. All figures, tables, and statistics must be exported directly to `results/tables/` (CSV) and `results/figures/` (300 DPI PNG).
8. **Strict Read-Only Old Notebooks:**
   - NEVER edit or modify any files in `old notebooks/`. They are strictly historical reference artifacts. Agents may only view or read them to extract details. All new development happens cleanly in `src/`.

## 7. Current Project State & Completed Milestones

All research phases (Phase 0 through Phase 11) are **🟢 Completed**:
1. **End-to-End Pipeline:** Leak-free two-stage IDS implemented in `src/` (Stage 1 Binary Gatekeeper + Stage 2 Multi-Tree Voting Ensemble).
2. **Generative Balancing:** PyTorch Conditional WGAN-GP oversampler with 1-Lipschitz continuity via gradient penalty trained strictly on attack partitions.
3. **Three Core Contributions Empirically Proved and Integrated into Manuscript:**
   - **Contribution 1 (SHAP Fidelity & Generative Precision):** Synthetic minority attack samples generated by WGAN-GP exhibit high attribution alignment ($\rho_s = 0.881$, $J_{10} = 0.750$, $S_C = 0.948$), outperforming SMOTE and ROS ($p < 0.01$). In Stage 2 isolated oracle evaluation on genuine attacks, WGAN-GP achieves a U2R F1 of $0.5075$ ($50.8\%$ precision and recall), delivering a **$5.8\times$ F1 gain over SMOTE** ($0.0867$, where precision collapses to $4.70\%$ due to synthetic interpolation artifacts).
   - **Contribution 2 (Stage-Wise SHAP Deconvolution):** Solves the severe feature attribution conflation observed in monolithic models ($\rho_s = 0.9246$, U2R top-10 Jaccard $53.85\%$). Two-stage deconvolution reduces correlation against baseline traffic to $\rho_s = 0.7086$ and collapses U2R feature overlap to just **$11.11\%$**, cleanly decoupling macro volumetric anomalies from micro privilege escalation indicators (`root_shell`, `num_file_creations`). Quantified in `results/tables/monolithic_shap_comparison.csv` and `results/tables/stage_importance_overlap.csv`.
   - **Contribution 3 (Stage-Aware Attack-Only GAN):** Conditioning exclusively on attack samples reduces training class imbalance from $1282.71:1$ down to $874.79:1$ and provides a **$4.6\times$ training speedup** ($253.22$\,s vs $1162.49$\,s) with zero sample memorization ($0.0\%$). Intra-class variance coverage audit (`results/tables/gan_mode_diversity.csv`) confirms coverage ratios $>125\%$ on rare attacks (U2R: $125.4\%$, R2L: $130.3\%$), proving the generator actively expands the minority manifold without mode collapse.
   - **Threshold Sweep & Operational Calibration:** Evaluated across $\tau \in [0.01, 0.95]$ on the actual test set (`results/tables/threshold_sweep_test.csv`). At calibrated sensitivity ($\tau = 0.05$), test attack recall is $85.75\%$, FPR is $0.0965$, rescuing U2R to $46.27\%$ and R2L to $23.29\%$ (Macro-F1 = $0.6595$). At sensitive mode ($\tau = 0.01$), attack recall is $97.02\%$, catching $49.25\%$ U2R and $53.80\%$ R2L (Macro-F1 = $0.7107$).
